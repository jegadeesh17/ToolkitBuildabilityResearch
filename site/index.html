How the agent works

The agent works in two passes. Pass 1 (steps 1–5) researches each app once and records its first answers. Pass 2 (steps 6–8) re-checks those answers with a second model, a judge and targeted re-research, and records every change. Search and page fetches run through Composio's search toolkit through its Python SDK; model calls go through OpenRouter. Every model call and tool call is logged, costed and budget-capped.

  1. Search Pass 1Four query templates per app, top three results each.
  2. Fetch Pass 1Up to six pages, official domains first, 20,000 characters each, saved as an evidence bundle.
  3. Extract Pass 1One schema-bound call answers every field from the pages only, with a verbatim quote per answer.
  4. Validate Pass 1Schema, four consistency rules and up to two repair calls; no evidence means “unknown”.
  5. Check quotes Pass 1Every quote must appear on the page it cites (whitespace, case and punctuation normalised).
  6. Second model Pass 2A model from a different family answers again from the same pages.
  7. Judge Pass 2A stronger model settles only the fields that disagree, fail the quote check or break a rule.
  8. Re-research Pass 2Unresolved fields get at most five more tool calls for new pages, then a fresh quote check.

Limitations and tradeoffs

  • The reference labels for the 20-app sample come from an independent AI agent, not a person, because hand-labelling 140 fields did not fit the time available. Agreement with them is not the same as accuracy; a person spot-checked 10 of their verdicts. The sample is small (140 fields), so treat the numbers as estimates with wide error bars.
  • Evidence comes from web search and plain page fetches. Documentation that only renders with JavaScript, sits behind a login or lives in PDFs is often missed; those fields show “unknown” with a reason.
  • The second model reads the same pages as the first, so a retrieval miss can fool both. Only re-research gathers new evidence, and it is capped at five tool calls per app.
  • “Buildable now” means a developer can obtain credentials alone today. It does not check rate limits, terms of service in depth, or approval timelines.
  • The free model named in the plan was unavailable (its provider rate-limited every call), so a different free model was piloted against the paid one; the paid model was chosen on schema validity and quote grounding.
  • Pass 1 was re-run once on the same evidence after two fixes found on non-sample apps (answers without evidence, and empty replies from reasoning overruns); every row uses the same pipeline version.
  • There is no browser-based verification loop: checks run on fetched page text, so content that only appears after JavaScript runs can be missed.
  • There is no hosted run button, since it would expose API keys and spend credits; the agent runs from the repository with your own keys, as the README shows.
